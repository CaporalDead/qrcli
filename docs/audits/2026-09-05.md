# Audit — 2026-09-05

Full application audit at **v0.2.0** (`main` @ the skills PR #21). Scope: code
correctness and robustness, security posture, supply chain, payload spec
conformance, CI/CD, packaging, governance. Method: manual review of every
source file plus an executed verification battery (below). Findings are
tracked as issues — this report is the snapshot, the issues are the work.

## Verdict

**Sound.** No vulnerability, no crash, no correctness defect found in the
shipped behavior. The end-to-end property that matters — *the rendered codes
actually scan, byte-exact* — is now proven with an independent decoder, not
assumed. Five hardening/edge-case findings filed (#22–#26), none affecting
current users on the documented paths.

the 2-module quiet zone (#2) and the default polarity scheme, in both normal
and `--invert` orientation.

## What is in good shape (verified, not vibes)

- **Supply chain, module side**: 1 direct dependency, 0 transitive, pinned by
  `go.sum`, vuln-free. Static `CGO_ENABLED=0` binaries with `-trimpath` and
  commit-stamped timestamps → reproducible-friendly.
- **Purity architecture**: `internal/render` and `internal/payload` are pure
  and exact-string tested; all I/O funnels through `run()` with injected
  streams. This is why the audit could fuzz 1.9 M cases in a minute.
- **Escaping**: single-pass `strings.NewReplacer` design makes double-escaping
  structurally impossible; fuzzing confirmed no property/line injection into
  vCard output.
- **CI/CD**: 3-OS matrix + lint + hermetic nix job on every PR; minimal
  workflow `permissions:`; release pipeline validated by two real releases
  across two `goreleaser-action` majors (#11 strategy paid off).
- **Error contract**: documented 0/1/2 exit codes hold under fuzzing.

## Notes and deliberate non-findings

- **Coverage gaps are honest ones**: `main()` (the `os.Exit` wrapper), the
  TTY-detection branch and the stdin read-error branch — all need a real
  process/TTY; the cost of exec-based tests outweighs the risk.
- **No ECI/charset signaling** in QR payloads (raw UTF-8): ecosystem-wide
  behavior of the underlying encoder, matches what modern scanners assume —
  recorded in #25 so nobody "fixes" it into a regression on old scanners.
- **Internal API trusts its callers**: `render.Options.QuietZone` is not
  range-limited and jagged bitmaps would panic — acceptable for an `internal`
  package whose only caller passes constants; noted for the day it goes public.
- **Args joined with spaces** (`qrcli a ""` encodes `"a "`): documented join
  semantics, not a defect.
- Lowercase `-l q` is accepted though the docs advertise uppercase — kept, as
  it can only widen, never break.

## Method note

All measurements above were executed on 2026-09-05 against commit `main` at
